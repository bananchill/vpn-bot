# TASK-003: Привязка конфигов к пользователю и Reply Keyboard

**Статус:** Ожидает апрува
**Приоритет:** Высокий
**Дата:** 2026-03-01

## Описание
Сейчас связь пользователя с конфигами уже есть на уровне БД (таблица `configs` имеет `user_id`), но навигация строится только на InlineKeyboard внутри сообщений. Нужно добавить постоянную Reply Keyboard под полем ввода — чтобы пользователь всегда видел кнопки "Создать конфиг" и "Мои конфиги" без необходимости возвращаться в меню через inline-кнопки.

## Что будет сделано

1. Создать новый модуль `bot/keyboards/reply.py` — функции для построения `ReplyKeyboardMarkup` главного меню пользователя.
2. Изменить `bot/handlers/start.py` — при `/start` отправлять Reply Keyboard вместе с приветственным сообщением (или в дополнение к нему).
3. Добавить в `bot/handlers/config.py` обработчики текстовых сообщений от Reply Keyboard (`F.text == "Создать конфиг"` и `F.text == "Мои конфиги"`), которые дублируют поведение одноимённых inline callback-обработчиков.
4. Убедиться, что FSM-состояние `waiting_for_name` не конфликтует с новыми текстовыми обработчиками (приоритет фильтра состояния выше).
5. Написать тесты для новых хендлеров и функции `reply_main_menu()`.

## Какие файлы будут затронуты

- `bot/keyboards/reply.py` — новый файл, `ReplyKeyboardMarkup` для главного меню пользователя
- `bot/keyboards/menus.py` — без изменений (inline-клавиатуры остаются)
- `bot/handlers/start.py` — изменение: добавить `reply_markup=reply_main_menu()` в ответ на `/start`
- `bot/handlers/config.py` — изменение: добавить два обработчика `F.text` для кнопок Reply Keyboard
- `tests/test_reply_keyboard.py` — новый файл, тесты

## Пользовательский сценарий

```
Пользователь: /start
Бот: Привет, username!
     Я помогу управлять VPN-конфигурациями.
     Выберите действие:
     [inline: Создать конфиг | Мои конфиги]
     [reply: Создать конфиг] [Мои конфиги]   ← постоянная панель под полем ввода

Пользователь: нажимает reply-кнопку "Мои конфиги"
Бот: Ваши конфиги:
     [inline-список конфигов]

Пользователь: нажимает reply-кнопку "Создать конфиг"
Бот: Введите название для нового конфига:
     (латинские буквы, цифры, без пробелов)
     — FSM переходит в waiting_for_name —

Пользователь: вводит "myconfig"
Бот: Создаю конфиг...
Бот: Конфиг «myconfig» создан!
     Ссылка для подключения: vless://...
     [inline: главное меню]
```

## Технические решения

- `ReplyKeyboardMarkup` с `resize_keyboard=True` и `persistent=True` — клавиатура остаётся видимой постоянно, не исчезает после нажатия.
- Обработчики `F.text` для Reply Keyboard регистрируются в `config.py` без фильтра состояния — они активны в любой момент кроме активного FSM-состояния. Фильтры состояний в aiogram 3 имеют более высокий приоритет при явном указании `State`.
- Inline-меню в `/start` не убирается — пользователь может пользоваться обоими типами навигации. Это сохраняет обратную совместимость.
- Новые текстовые хендлеры (`F.text == "Создать конфиг"`, `F.text == "Мои конфиги"`) должны быть зарегистрированы до FSM-хендлеров, чтобы не перехватываться в состоянии `waiting_for_name` — это обеспечивается порядком регистрации и отсутствием State-фильтра.

## Критерии приёмки

- [ ] При `/start` под полем ввода появляется Reply Keyboard с кнопками "Создать конфиг" и "Мои конфиги"
- [ ] Нажатие reply-кнопки "Мои конфиги" показывает список конфигов текущего пользователя (только его конфиги, не чужие)
- [ ] Нажатие reply-кнопки "Создать конфиг" запускает FSM-флоу создания конфига
- [ ] В состоянии `waiting_for_name` ввод текста интерпретируется как название конфига, а не как команда меню
- [ ] Reply Keyboard не исчезает после нажатий (persistent)
- [ ] Тесты для `reply_main_menu()` проходят
- [ ] Тесты для новых текстовых хендлеров проходят
- [ ] `uv run ruff check .` без ошибок

## Вне скоупа

- Изменение структуры БД — связь user-config уже реализована через `user_id` в таблице `configs`
- Удаление Inline Keyboard — оба типа клавиатур существуют параллельно
- Добавление новых пунктов меню (статистика, настройки и т.п.)
- Отдельная Reply Keyboard для администраторов
