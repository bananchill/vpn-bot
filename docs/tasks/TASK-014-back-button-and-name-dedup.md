# TASK-014: Кнопка "Отмена" и дедупликация имён конфигов

**Статус:** Ожидает апрува
**Приоритет:** Средний
**Дата:** 2026-03-02

## Описание
В flow создания конфига есть два недостатка. Первый: когда бот просит ввести название конфига, у пользователя нет способа выйти из этого состояния — нужна inline-кнопка "Отмена". Второй: если имя уже занято, бот показывает общую ошибку вместо того, чтобы различать случай "это ваш конфиг" и "имя занято другим пользователем".

## Что будет сделано

1. В `bot/keyboards/menus.py` — добавить функцию `cancel_config_creation()`, возвращающую `InlineKeyboardMarkup` с одной кнопкой "Отмена" (callback_data: `"cancel_config_creation"`).

2. В `bot/handlers/config.py`, функции `start_create_config` и `reply_create_config` — добавить `reply_markup=cancel_config_creation()` к сообщению "Введите название...".

3. В `bot/handlers/config.py` — добавить callback-хендлер `cancel_config_creation_handler` на `F.data == "cancel_config_creation"`: очистить FSM state, вернуть главное меню через `edit_text` (для callback) или `answer` (для reply).

4. В `bot/handlers/config.py`, функция `process_config_name` — добавить блок дедупликации перед вызовом `create_config`. Использовать существующий метод `config_repo.get_by_email(name)`:
   - Если найден конфиг и `config.user_id == user.id` → очистить FSM, показать detail-меню (`config_detail_menu`) этого конфига.
   - Если найден конфиг и `config.user_id != user.id` → не очищать FSM, показать сообщение "Имя «{name}» уже занято, попробуйте другое:" и ждать нового ввода.
   - Если не найден → продолжить создание как обычно.

5. В `bot/handlers/config.py` — при показе сообщения о некорректном названии (валидация) и сообщения "попробуйте другое" (дедупликация) также прикреплять `reply_markup=cancel_config_creation()`, чтобы кнопка "Отмена" всегда была видна пока FSM активен.

## Какие файлы будут затронуты

- `bot/keyboards/menus.py` — изменение, добавление функции `cancel_config_creation()`
- `bot/handlers/config.py` — изменение: добавление `reply_markup` в существующие хендлеры, новый callback-хендлер отмены, блок дедупликации в `process_config_name`
- `bot/db/repositories/config_repo.py` — изменений нет, используется существующий метод `get_by_email`

## Пользовательский сценарий

**Сценарий 1: отмена через кнопку**
```
Пользователь: [нажимает "Создать конфиг"]
Бот: Введите название для нового конфига:
     (латинские буквы, цифры, дефис или подчёркивание — без пробелов)
     [кнопка: Отмена]
Пользователь: [нажимает "Отмена"]
Бот: [редактирует сообщение → главное меню с кнопками]
```

**Сценарий 2: имя принадлежит этому пользователю**
```
Пользователь: [вводит "myconfig"]
Бот: Конфиг «myconfig» уже существует.
     [показывает detail-меню этого конфига: трафик, ссылка, удалить, назад]
```

**Сценарий 3: имя занято другим пользователем**
```
Пользователь: [вводит "takenname"]
Бот: Имя «takenname» уже занято, попробуйте другое:
     [кнопка: Отмена]
Пользователь: [вводит "myuniquename"]
Бот: Создаю конфиг...
Бот: Конфиг «myuniquename» создан! ...
```

**Сценарий 4: отмена через reply-кнопку (BTN_CREATE_CONFIG)**
```
Пользователь: [нажимает reply-кнопку "Создать конфиг"]
Бот: Введите название для нового конфига:
     [кнопка: Отмена]
Пользователь: [нажимает "Отмена"]
Бот: [новое сообщение с главным меню, FSM очищен]
```

## Технические решения

- Кнопка "Отмена" реализуется как inline-кнопка (не reply), чтобы не засорять reply-клавиатуру пользователя.
- Callback-хендлер отмены должен быть зарегистрирован без фильтра по FSM-состоянию (или с `StateFilter(ConfigCreateStates.waiting_for_name)`), чтобы не конфликтовать с другими хендлерами.
- Для `start_create_config` (callback) отмена редактирует то же сообщение (`edit_text`) с `main_menu()`. Для `reply_create_config` (message) отмена отправляет новое сообщение (`answer`) с `main_menu()`, так как исходное сообщение — текст из reply-клавиатуры.
- Метод `get_by_email` в `ConfigRepository` уже существует и возвращает `ConfigDTO | None` — новый метод в репозитории не нужен.
- Дедупликация происходит до проверки лимита конфигов: сначала проверяем имя, потом лимит. Это даёт более точное сообщение об ошибке.

## Критерии приёмки

- [ ] При вводе команды создания конфига (через inline или reply кнопку) у сообщения "Введите название" есть inline-кнопка "Отмена"
- [ ] Нажатие "Отмена" очищает FSM state и возвращает главное меню
- [ ] Повторный ввод своего существующего имени открывает detail-меню этого конфига (FSM очищен)
- [ ] Ввод занятого чужого имени показывает сообщение "Имя «{name}» уже занято, попробуйте другое:" с кнопкой "Отмена", FSM остаётся активным
- [ ] При сообщениях об ошибке валидации кнопка "Отмена" также присутствует
- [ ] Ввод свободного имени создаёт конфиг как раньше

## Вне скоупа

- Изменение логики валидации имени конфига (формат, длина)
- Кнопка "Отмена" для других FSM-flow (например, /admin)
- Проверка занятости имени на стороне 3x-ui панели (только локальная БД)
- Пагинация списка конфигов
